Infra Portal

A self-service portal for requesting servers on Proxmox VE and AWS

Muthu · November 2026 · github.com/Muthujar/infra-portal

The problem

Getting a server today means a ticket and a wait

  • Developers raise a ticket and wait for the DevOps team.
  • Servers are built by hand, so they differ.
  • There is no clear record of who approved what.
  • Forgotten test servers keep using capacity.

Goal: a catalog, an approval step and automation, like VMware vRealize Automation (Aria).

The solution

Four steps from request to ready server

1 · DEVELOPER

Request

Picks a server, environment and lease.

2 · API

Check

Validates the input and team quota.

3 · TEAM LEAD

Approve

Approves it. PROD needs an admin. Terraform is generated.

4 · WORKER

Build

Runs Terraform, then configures the server.

Every change is in the audit log. Servers are deleted when their lease ends.

Architecture

A queue and worker handle the slow work

Request life cycle

One state machine controls every status change

  • Only allowed moves are accepted.
  • Two people cannot act on a request at once.
  • Every change is written to the audit log.
